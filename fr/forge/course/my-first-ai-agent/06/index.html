Posez la barrière d’approbation (avant de commencer)

Une capacité d’agir sans barrière, c’est une dette. Réglez ça avant que l’agent touche quoi que ce soit. Les approbations Smart ↗ laissent passer les étapes peu risquées et s’arrêtent dans le doute. Manual est plus lent, et parfaitement bien. Les modes tout-auto (parfois étiquetés YOLO) sont réservés aux experts — laissez-les éteints pour ce cours.

Ça vit dans Settings → Safety → Approval Mode. Smart est le défaut du cours. Off est celui à éviter — c’est le mode tout-auto.

IMG
Steps · tap the number to check0/2
  1. Mettez Approval Mode sur Smart ou Manual — jamais Off.
  2. Décidez votre règle maintenant, pour ne pas la décider sous pression : approuver les étapes à l’intérieur du dossier sur lequel vous travaillez, refuser tout ce qui supprime ou sort de ce dossier.

Connaître votre coût (léger)

Le fournisseur ↗ (OpenRouter, OpenCode, …) est là où vit la clé ; le modèle, c’est la capacité et le prix. Les paliers gratuits ont quand même des limites. Avant de blâmer le modèle, sachez ce qui est déjà chargé dans une session vide.

Steps · tap the number to check0/2
  1. Notez quel fournisseur et quel modèle sont sélectionnés — vous voudrez savoir lequel a fait le travail.
  2. Optionnel : ouvrez la vue contexte / usage dans Desktop et notez les deux plus grosses parts (outils / compétences / mémoire).
Une habitude qui multiplie discrètement la facture : changer de modèle en pleine session. Chaque bascule invalide le cache de prompt du modèle d’arrivée, et vous repayez plein tarif les tokens d’entrée pour tout ce qui est déjà chargé — outils, skills, mémoire, historique. Ce n’est pas une bizarrerie d’Hermes ; c’est un fondamental de l’inférence. Choisissez un modèle par session et gardez-le ; confiez plutôt les tâches annexes aux modèles auxiliaires.

Mettez votre agent au travail

Choisissez une voie. Même travail des deux côtés : installer la compétence, consentir une fois, vider la file, ouvrir le reçu. Le unbroker officiel Hermes, c’est le people-search US — pas cette mission.

Vous êtesCompétenceDroit
Vous vivez à Genève / en Suisseunbroker-genLPD / LPD, lettres en français
Vous êtes résident UE ou Royaume-Uniunbroker-euGDPR Arts. 17 and 21

Lisez l’invite d’approbation une fois. Approuvez les formulaires officiels de désinscription et les écritures dans le dossier que vous avez nommé. Refusez les suppressions, tout ce qui sort du dossier, et toute tentative de joindre une pièce d’identité.

Vous ne lancez ça que sur vous-même. Le moteur refuse de planifier sans consentement enregistré. Pas un conseil juridique. Ce cours ne connecte pas de compte e-mail : l’agent soumet des formulaires web dans le navigateur ; tout ce qui est une lettre est un brouillon .txt que vous envoyez depuis votre propre boîte. Les bureaux de crédit qui exigent une pièce d’identité (CRIF, SCHUFA, Experian…) restent dans le digest.
Steps · tap the number to check0/4
  1. Installez une compétence (voie A ou B). Nouvelle session pour que Hermes la charge.
  2. Collez la ligne correspondante ci-dessous. Donnez nom, adresse, e-mail, téléphone quand il les demande — une fois.
  3. Laissez-le vider la file. Approuvez les recherches et les formulaires sans pièce d’identité. Refusez les suppressions et les scans d’identité. N’attendez pas qu’il envoie des e-mails — copiez les brouillons de drafts/ dans votre propre boîte.
  4. Quand il s’arrête, ouvrez unbroker-receipt.md hors ligne. Si le fichier manque, la mission a échoué.

Où la session s’arrête et où la mémoire commence

Tout ce que vous venez de faire vit dans cette session. Fermez-la : la conversation a disparu — la compétence installée reste, mais ce que l’agent a compris de votre travail, non. Cet écart, c’est tout le sujet de la Partie II.

D’abord, les contrôles de session. Les longs chats remplissent la fenêtre ; voici comment vous la tenez :

  • ·/context · /compress — voir ce qui est chargé, et le réduire
  • ·/undo · /retry · /branch — contrôle de conversation
  • ·/rollback + checkpoints — fichiers déjà changés (ce n’est pas /undo)
POST

Rien de tout ça n’est de la mémoire, pourtant. Ça range seulement le chat où vous êtes. Tout ce que la Partie II ajoute — des notes qu’il garde, un dossier de vos écrits qu’il peut chercher, des tâches qui tournent pendant que vous dormez — part d’une idée : si vous voulez que ce soit gardé, il faut l’écrire dans un fichier. C’est la leçon 07.

Autres façons de déployer

▸Backends d’outils et isolation de la machine

Les outils shell utilisent un backend terminal. Sur une machine dédiée, vous pouvez laisser les outils plus libres. Sur une machine personnelle, Docker ↗ (ou un VPS) est le défaut responsable — pas « plus tard si vous en avez envie ».

  • ·Processus sur machine dédiée — ok quand la boîte est labo seulement
  • ·Backend Docker — commandes isolées de l’OS hôte (compromis exigé sur un ordinateur du quotidien)
  • ·SSH / VPS / sandboxes cloud — les outils tournent sur une autre machine que vous pouvez effacer
  • ·Infra à vous vs modèles API cloud — l’endroit du cerveau est indépendant du backend d’outils ; les cerveaux cloud envoient quand même le contenu du chat hors de la boîte
  • ·Ops multi-machines — Desktop ici, workers ou gateway sur un VPS
Pour une isolation de production, des hôtes d’équipe partagés, ou des contraintes de conformité, contactez Delta V — déploiements Hermes sur mesure par nos ingénieurs.
