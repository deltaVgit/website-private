Lui apprendre à se souvenir

Le chat d’aujourd’hui disparaît quand vous le fermez. Ce que vous voulez garder doit être écrit.

00sur 05 sections derrière vous

Où il range les choses

La Partie II commence ici parce qu’un agent qui oublie vos préférences chaque matin vous fait vous répéter pour toujours. Votre agent range les choses à trois endroits, et ça vaut de savoir lequel est lequel.

OùCe que ça tientCombien
Le carnetSOUL.md, MEMORY.md, USER.md — lus au début de chaque chatPetit, exprès
Les anciens chatsDe vieilles conversations qu’il peut rechercherAutant que le disque le permet
Vos notesUn dossier de vos propres notes qu’il peut lire (leçon suivante)Autant que vous écrivez

Il écrit maintenant, il lit la prochaine fois

L’agent lit ses notes une fois, au démarrage d’un chat. Donc s’il écrit quelque chose en cours de conversation, demander « tu te souviens ? » dans ce même chat peut encore revenir vide — le fichier est juste, il ne l’a simplement pas relu. Vérifiez le fichier, puis ouvrez un nouveau chat pour le voir en action.

Si MEMORY.md a la ligne et que cette session l’ignore — fermez et rouvrez avant de blâmer l’agent.

MEMORY.md et USER.md

MEMORY.md est le carnet de l’agent — votre montage, vos conventions, ce qu’il a appris. USER.md est votre fiche : nom, préférences, choses à éviter. L’agent écrit les deux ; vous pouvez les éditer dans n’importe quel éditeur de texte. Ce qu’il n’écrit jamais, il ne le garde jamais.

Les deux sont petits exprès, parce qu’ils sont lus au début de chaque chat — chaque ligne que vous ajoutez est une ligne que l’agent traîne pour toujours. Gardez décisions, préférences et corrections ; jamais de transcriptions. Quand ils débordent : fusionnez des lignes, raccourcissez, supprimez ce qui est périmé.

Tout retenir, c’est ne rien retenir. Préférez des faits denses.

Ça fait trois fichiers dans votre Hermes home, tous chargés à chaque chat, donc ça vaut d’être précis sur lequel est lequel :

FichierIl tientQui l’écrit
SOUL.mdQui l’agent est — rôle, ton, limites strictesVous, une fois — ça change rarement
MEMORY.mdCe qu’il a appris — votre montage, conventions, décisionsL’agent, au fil du travail ; vous pouvez éditer
USER.mdQui vous êtes — nom, préférences, liste d’évitementsL’agent, à partir de ce que vous lui dites
Une préférence du type « garde les réponses courtes » va dans USER.md, pas dans SOUL.md. L’identité, c’est ce que l’agent est pour tout le monde ; la mémoire, c’est ce qu’il sait de ce montage et de cette personne.

Depuis la v0.20.5, cette paire porte plus loin que vos chats : les jobs planifiés (cron) chargent aussi MEMORY.md et USER.md, se réveillent en connaissant déjà vos préférences, et peuvent enregistrer de nouveaux faits durables pour les exécutions futures. La mémoire est partagée par le profil, pas par le job — un fait durable écrit par un job sert à tous les autres. La leçon 11 détaille ce que ça change.

Fichier plutôt que l’app : les produits de chat fermés n’offrent pas cette honnêteté.

Prouvez qu’il se souvient

La façon de se tromper ici : si vous ne fermez pas vraiment le chat, le fait est encore à l’écran et l’agent vous le répète sans jamais lire le fichier. Une session à moitié fermée passe toujours. Fermez-la pour de bon.
Steps · tap the number to check0/4
  1. Dites à l’agent : « Retiens que le nom de code du projet est HARNESS-01 et que je préfère les réponses courtes. »
  2. Demandez-lui d’écrire ça dans la mémoire durable.
  3. Ouvrez MEMORY.md / USER.md sur le disque et vérifiez que les lignes sont vraiment là.
  4. Fermez le chat complètement. Ouvrez-en un nouveau. Demandez : « Quel est le nom de code de mon projet, et quelle longueur de réponse je préfère ? »

Mémoire vs hallucination

Sans mémoire, le modèle comble les trous avec de l’assurance. Avec mémoire et sources, il consulte d’abord. Encore faillible — mais vérifiable par vous et par l’agent.
